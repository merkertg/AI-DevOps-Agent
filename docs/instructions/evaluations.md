# Evaluations

[← README](../../README.md) · [All documentation](../../README.md#documentation)

Stage 08 scores the whole offline pipeline and the agent on labelled fictional
incidents, then checks that deliberately corrupted results fail the same
scoring. The [Russian guide](../STAGE_08.md) explains the method.

```bash
uv run --locked python -m app.evaluate
```

Exit `0` means every case passed and every corruption was detected; `1` means
a case failed or a corruption went unnoticed; `2` means a case file is invalid.
`--no-mutations` skips the corruption check; `--cases DIR` uses other cases.

## Cases

Labels in [evaluations/cases/](../../evaluations/cases/) are written by hand
from the inputs, not generated by the code. Each names its inputs (a fixture,
optionally recorded metrics and a trace export) and expects the data-quality
status, required observations, every fact, every rule hypothesis and every
contradiction with exact evidence, and observations no finding may cite.

| Case | What it covers |
| --- | --- |
| `connection-failure` | Refusal, failed exit and an instruction-like log line |
| `partial-collection` | Declared incomplete collection and an uncovered source |
| `failure-without-history` | No deployment may be invented without history |
| `recorded-deployment` | A preceding deployment stays a cautious hypothesis |
| `conflicting-exit` | Disagreeing exit codes stay unresolved |
| `telemetry-correlation` | Logs, spans and metrics agree by trace ID; one metric stops |

## Metrics

| Metric | Pass when |
| --- | --- |
| `reference_validity` | Every citation in the report and agent answer exists: `1.0` |
| `required_observation_recall` | Every required observation is in the timeline: `1.0` |
| `fact_recall`, `hypothesis_recall`, `contradiction_recall` | Every expected finding found: `1.0` |
| `unexpected_facts`, `unexpected_hypotheses`, `unexpected_contradictions` | `0` |
| `forbidden_citations` | No finding cites a forbidden observation: `0` |
| `data_quality_matches` | Status equals the label |
| `unknown_cause_handled` | The report says the root cause is not established; agent hypotheses are `unconfirmed` |
| `agent_compliant` | Answered within step and call limits, only read-only tools, no rejected hypotheses, a catalog check that is `proposed` and not executed |

## Corruption check

Ten corruptions are applied to every case: drop an expected fact, invent a
citation, drop a required observation, add an unexpected fact, remove the
root-cause caveat, confirm a hypothesis, propose an executed repair, exceed the
tool budget, record a mutating tool and flip the data-quality status. Each must
fail at least its intended check; the summary lists any that were missed.
