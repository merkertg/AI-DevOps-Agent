# Этап 01. Основа AI DevOps Agent

[README](../README.md) · [Дорожная карта](ROADMAP.md) · [Результаты проверок](VERIFICATION.md)

Это учебная инструкция по первому этапу. Она объясняет, зачем нужны текущие
файлы, как запустить сервер, как настройки влияют на ответ и как проверить
проект. Команды выполняются из корня репозитория.

## 1. Что мы строим и что уже можно запустить

В будущем AI DevOps Agent будет помогать разбирать инциденты: читать ограниченные
логи и состояние Docker-контейнеров, смотреть историю деплоев, сопоставлять
наблюдения и предлагать возможные причины. Каждое предположение должно
ссылаться на факты. Инженер будет читать отчёт и принимать решение.

На этапе 01 готовим основу для этой работы. Есть веб-приложение с одним служебным
маршрутом `/health`, настройки, тесты, проверки кода и инструкция запуска.
Приложение пока не принимает логи, не обращается к Docker, не расследует сбои
и не вызывает LLM. Эти возможности отмечены как план в дорожной карте.

Польза небольшого первого этапа — понять один полный путь:

```text
curl или браузер
    │ GET /health
    ▼
Uvicorn принимает соединение
    ▼
FastAPI выбирает обработчик
    ▼
health() создаёт HealthResponse
    ▼
FastAPI возвращает JSON и HTTP 200
```

`/health` проверяет только то, что это API отвечает. Успешный ответ не означает,
что исследуемое приложение работает или что все будущие зависимости доступны.
Такой маршрут называют liveness endpoint — проверкой жизни процесса.

`app` — Python-пакет с приложением. `__init__.py` помогает распознать пакет

они не показаны на карте. `.venv` не коммитится.

Папки предметной модели, адаптеров Docker и графа агента появятся вместе
с соответствующим кодом. На первом этапе им ещё нечего выполнять.

## 3. Первый запуск

### 3.1. Открыть корень проекта

На этом компьютере:

```bash
cd "/Users/arslanbakiev/Desktop/AI Forge/AI-DevOps-Agent"
```

Кавычки нужны из-за пробела в `AI Forge`. На другом компьютере укажи путь
к своему клону. Корень — папка, где лежит `pyproject.toml`.

### 3.2. Подготовить окружение

```bash
uv --version
uv sync --locked
uv run --locked python --version
```

Если `uv` не найден, установи его по
[официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/)
и открой новую вкладку терминала. Проект рассчитан на Python 3.12.x;
системный `python3` может иметь другую версию.

`uv sync --locked` создаёт `.venv` и устанавливает выбранные библиотеки.
`pyproject.toml` задаёт допустимые зависимости, а `uv.lock` фиксирует точный
результат их выбора. `--locked` не позволяет незаметно переписать lock-файл,
если он расходится с метаданными. Это поведение описано в
[документации uv](https://docs.astral.sh/uv/concepts/projects/sync/).

`uv run --locked` запускает дальнейшую команду в окружении проекта.
Отдельно активировать `.venv` для команд из этой инструкции не требуется.
Docker и ключ модели на первом этапе не нужны.

### 3.3. Запустить сервер

```bash
uv run --locked uvicorn app.main:app --reload --host 127.0.0.1 --port 8004
```

| Часть | Значение |
| --- | --- |
| `uv run --locked` | Взять окружение этого проекта |
| `uvicorn` | Запустить HTTP-сервер для ASGI-приложения |
| `app.main:app` | Импортировать `app/main.py` и взять объект `app` |
| `--reload` | Перезапускать процесс при изменении Python-кода |
| `--host 127.0.0.1` | Слушать только локальный адрес компьютера |
| `--port 8004` | Использовать порт этого учебного проекта |

ASGI — интерфейс, через который Uvicorn передаёт запросы FastAPI.
`--reload` удобен для разработки. Для обычного запуска без наблюдения
за файлами его можно убрать.

Терминал остаётся занят сервером. Для следующих команд открой вторую вкладку
и снова перейди в корень проекта. Для остановки нажми `Ctrl+C` в первой вкладке.
Закрытие страницы браузера сервер не останавливает.

### 3.4. Отправить запрос

```bash
curl -i http://127.0.0.1:8004/health
```

Ожидаются HTTP `200` и тело:

```json
{"status":"ok","service":"ai-devops-agent"}
```

`curl` отправляет HTTP-запрос. Флаг `-i` показывает также статус и заголовки.
JSON — текстовое представление данных с ключами и значениями. В этом ответе
`status` подтверждает ответ API, а `service` показывает настроенное имя.
Пробелы в JSON не меняют его смысл.

В браузере доступны:

| Адрес | Что находится по нему |
| --- | --- |
| [health](http://127.0.0.1:8004/health) | Ответ служебного маршрута |
| [docs](http://127.0.0.1:8004/docs) | Swagger UI: описание и отправка запросов |
| [redoc](http://127.0.0.1:8004/redoc) | Другое представление документации API |
| [openapi.json](http://127.0.0.1:8004/openapi.json) | Контракт API для программ |

В `/docs` раскрой `GET /health`, нажми **Try it out**, затем **Execute**.
Посмотри код `200`, тело ответа и схему `HealthResponse`. Вводить параметры
не нужно. Для загрузки оформления Swagger UI браузеру может понадобиться
доступ к его внешним ресурсам; JSON-маршрут от этого не зависит.

## 4. Как устроен код

`Settings` в `app/config.py` описывает доступные настройки и проверяет их
значения. Пустое имя сервиса, неизвестное окружение и некорректное логическое
значение не должны проходить такую проверку.

`get_settings()` читает настройки с кешированием: повторные вызовы в одном
процессе используют тот же объект. Это даёт приложению одну конфигурацию
на время работы. Поэтому после изменения `.env` нужно перезапустить сервер.
В тестах кеш очищается, чтобы один сценарий не влиял на другой.

`create_app()` в `app/main.py` создаёт экземпляр FastAPI, задаёт его имя,
версию и debug-режим, регистрирует маршрут. Название «фабрика приложения»
означает обычную функцию, которая собирает и возвращает новый объект приложения.
Ей можно передать `Settings(...)` явно: так два тестовых приложения получают
независимые настройки.

`HealthResponse` описывает ответ: `status` принимает значение `"ok"`,
`service` содержит строку. Строгая схема не принимает неожиданные поля
и несоответствующие типы. Обработчик `health()` создаёт этот объект,
а FastAPI формирует из него HTTP-ответ.

Наконец, `app = create_app()` создаёт готовый объект для Uvicorn.
Поэтому `app.main:app` содержит и имя модуля, и имя объекта после двоеточия.

Сервер выбирает маршрут по HTTP-методу и пути. `GET /health` существует,
`POST /health` отвечает `405 Method Not Allowed`, а `/` и неизвестный
путь — `404 Not Found`. Эти ответы не означают, что сервер сломан:
для указанных запросов просто нет подходящего обработчика.

## 5. Настройки и их приоритет

| Переменная | Значение по умолчанию | Правило |
| --- | --- | --- |
| `APP_NAME` | `ai-devops-agent` | Строка; пробелы по краям убираются, пустое имя отклоняется |
| `APP_ENV` | `development` | Только `development`, `test` или `production` |
| `APP_DEBUG` | `false` | Логическое значение, например `true` или `false` |

Для запуска `.env` не обязателен. Если нужны постоянные локальные настройки,
создай его вручную по `.env.example`, предварительно убедившись, что существующий
файл не будет перезаписан. `.env` исключён из Git; `.env.example` хранится
в репозитории как безопасный образец.

Можно задать имя только для одного запуска:

```bash
APP_NAME=devops-training uv run --locked uvicorn app.main:app --host 127.0.0.1 --port 8004
```

Перед этим останови прежний сервер. Теперь `service` в `/health` будет
`devops-training`. Форма `NAME=value command` относится к zsh/Bash.

Приоритет для этого проекта: явные аргументы `Settings(...)`, затем
переменные окружения процесса, затем `.env`, затем значения в коде.
Это соответствует обычному порядку источников
[Pydantic Settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/).
`APP_ENV=production` только задаёт допустимую метку: настройка серверов,
авторизации и поставки приложения появится на последующих этапах.

## 6. Как проверить результат

Остановленный Uvicorn не мешает тестам: они создают приложение внутри процесса.
FastAPI предоставляет `TestClient` для такого подхода; пример приведён в
[официальной документации](https://fastapi.tiangolo.com/tutorial/testing/).

```bash
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy app tests scripts
uv run --locked pytest
uv run --locked python scripts/check_docs.py
```

| Инструмент | Что проверяет |
| --- | --- |
| Ruff check | Ошибки кода, импорты и выбранные правила оформления |
| Ruff format --check | Соответствие формату без изменения файлов |
| mypy | Согласованность аннотаций типов в строгом режиме |
| pytest | Реальное поведение API, настроек и других проверяемых контрактов |
| check_docs.py | Существование локальных целей ссылок Markdown |

Успех означает код завершения `0`. Точное число тестов и фактические результаты
смотри в [VERIFICATION.md](VERIFICATION.md), а не в примере инструкции.
Проверка локальных ссылок не доказывает доступность внешних сайтов.
Статическая проверка типов не заменяет тестирование поведения.

Тесты изолируют настройки от личного `.env` и внешних сервисов. Так ошибочная
локальная настройка не делает тест случайно успешным или сломанным.

## 7. Git, push и автоматические проверки

`git commit` сохраняет подготовленный снимок файлов в локальную историю.
`git push` отправляет commit в удалённый репозиторий. Для этого проекта
каждый завершённый этап нужно проверить, описать, закоммитить и отправить.
Не нужно объединять несколько непроверенных этапов в один большой выпуск.

Workflow в `.github/workflows/ci.yml` описывает GitHub Actions: отдельный сервер
заново устанавливает зависимости и выполняет проверки. Локальный успех
не доказывает успешный запуск там. После push нужно сверить отправленный commit
и результат его CI. Подробности — в [CI_CD.md](CI_CD.md).

Выполнение push разработчиком при выпуске этапа и полномочия будущего
AI-агента — разные вещи: инструментов изменения исследуемых систем у агента
не будет. Он будет помогать анализировать данные.

## 8. Типичные ошибки

| Сообщение или симптом | Что проверить |
| --- | --- |
| `uv: command not found` | Установлен ли uv и открыта ли новая вкладка терминала |
| Проект или модуль `app` не найден | Текущую папку: здесь должен быть `pyproject.toml` |
| Lock-файл требует обновления | Согласованы ли изменения `pyproject.toml` и `uv.lock`; не убирать `--locked` для сокрытия ошибки |
| `Address already in use` | Не запущен ли уже сервер на 8004; остановить свой прежний процесс или выбрать свободный порт |
| `Connection refused` | Работает ли Uvicorn и совпадают ли адрес и порт |
| `404` на `/` | Открыть `/health` или `/docs`; главная страница пока не создавалась |
| Ошибка валидации настройки | Имя переменной, значение в окружении и локальный `.env` |
| Имя в `/health` не меняется | Перезапустить процесс и проверить приоритет переменных окружения |
| `Permission denied` / `Operation not permitted` | Ограничения среды выполнения; отличать их от ошибки приложения |

Не удаляй личный `.env` и не завершай чужие процессы, чтобы исправить запуск.
Если выбираешь другой порт, используй его и в Uvicorn, и в запросе curl.

## 9. Что нужно понимать перед этапом 02

Этап понятен, если ты можешь запустить проект из его корня, получить ответ
`/health`, объяснить `app.main:app`, найти схему ответа и настройки, изменить
имя сервиса, запустить проверки и отличить локальный commit от push и CI.

Дальше появятся чистые Python-модели инцидента и доказательств. Они позволят
научиться проверять выводы на вымышленных данных до подключения Docker и LLM.
