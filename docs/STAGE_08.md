# Этап 08. HTTP API, оценки и поставка контейнера

[← README](../README.md) · [Этап 07](STAGE_07.md) · [Дорожная карта](ROADMAP.md) · [Проверки](VERIFICATION.md)

## 1. Что должно получиться

Это завершающий этап учебного пути. К уже готовым частям добавляются три вещи:

1. **HTTP API расследований.** Расследование можно сохранить, прочитать,
   проверить и передать агенту по HTTP. Доступ — только по токенам.
2. **Оценки качества.** Шесть известных вымышленных инцидентов с вручную
   записанными ожидаемыми результатами. Программа сравнивает с ними свой
   вывод и проверяет, что заметит намеренно испорченный результат.
3. **Контейнер.** Образ API собирается и проверяется в CI.

Автоматическое исправление исследуемых систем в проект по-прежнему не входит:
и API, и агент только читают и предлагают.

## 2. Как устроен путь пользователя

```text
клиент ── Bearer-токен ──→ POST /investigations (вымышленная фикстура JSON)
                              ↓ разбор этапа 03, обезличивание
                         канонический вход → SQLite (только добавление)
                              ↓
GET /investigations/{id} ── сохранённый отчёт байт в байт
GET …/verification ──────── хеши и повторное построение отчёта
POST …/agent ────────────── офлайн-агент этапа 06, ничего не выполняется
```

Решение о границах записано в
[ADR 0007](adr/0007-token-scoped-api-and-container.md).

## 4. Включить API

По умолчанию маршруты расследований закрыты: любой запрос получает `403`.
Чтобы открыть их, задай **хеши** токенов, а не сами токены:

```bash
printf %s "$READ_TOKEN" | shasum -a 256
printf %s "$WRITE_TOKEN" | shasum -a 256
```

Результаты запиши в `APP_READ_TOKEN_SHA256` и `APP_WRITE_TOKEN_SHA256`
(в `.env` или в окружение). Сами токены храни отдельно и не коммить. Хеш
нельзя развернуть обратно в токен, поэтому утечка настроек не раскрывает
секрет. Сравнение хешей выполняется за постоянное время.

| Токен | Что разрешено |
| --- | --- |
| Записи | Сохранять и всё, что разрешено токену чтения |
| Чтения | Список, чтение отчёта, проверка, запуск агента |

`/health` остаётся открытым: он сообщает только, что сервис отвечает.

## 5. Сохранить и прочитать расследование

```bash
uv run --locked uvicorn app.main:app --host 127.0.0.1 --port 8004
curl -s -X POST http://127.0.0.1:8004/investigations -H "Authorization: Bearer $WRITE_TOKEN" -H "Content-Type: application/json" --data-binary @fixtures/stage05/after_deployment.json
curl -s http://127.0.0.1:8004/investigations/inv-3dec28b1f8811404869dc78b -H "Authorization: Bearer $READ_TOKEN"
curl -s -X POST http://127.0.0.1:8004/investigations/inv-3dec28b1f8811404869dc78b/agent -H "Authorization: Bearer $READ_TOKEN"
```

Первый `POST` отвечает `201` и заголовком `Location`, повторный — `200`
с `"created": false` и исходным временем сохранения. Идентификатор вычисляется
из хеша входа, поэтому для этой фикстуры он одинаков на любой машине.

Тело запроса — фикстура в [формате этапа 03](instructions/offline-investigation.md),
не больше 1 MiB. API **не принимает** путей к файлам, репозиториям, сокетам или
адресов Prometheus: иначе клиент мог бы заставить сервер читать чужие данные.
Сбор из Docker, Git и телеметрии остаётся в CLI на машине разработчика.

## 6. Понятные ошибки

| Код | Когда |
| --- | --- |
| `400` | Тело — не корректная фикстура |
| `401` | Нет токена или токен неизвестен |
| `403` | API не настроен или у токена нет права записи |
| `404` | Неизвестный или неправильный идентификатор |
| `409` | Запись не прошла проверку целостности или воспроизводимости |
| `413` / `415` | Тело больше 1 MiB / не `application/json` |
| `503` | Хранилище недоступно |

Текст ошибок фиксированный и не повторяет присланные значения.

## 7. Оценки: что измеряем

```bash
uv run --locked python -m app.evaluate
```

Для каждого из шести случаев программа выполняет весь офлайн-путь (разбор,
телеметрия из записанных файлов, отчёт, офлайн-агент) и сравнивает JSON-вывод
с метками:

- **ссылочная достоверность** — каждая ссылка в отчёте и в ответе агента
  указывает на существующее наблюдение или факт;
- **полнота обязательных наблюдений** — все нужные наблюдения есть на шкале;
- **факты, гипотезы и противоречия** — найдены все ожидаемые с точными
  ссылками и нет лишних;
- **запрещённые ссылки** — ни один вывод не опирается, например, на строку лога,
  похожую на инструкцию;
- **неизвестная причина** — отчёт прямо говорит, что первопричина не
  установлена, а гипотезы агента остаются `unconfirmed`;
- **соблюдение ограничений агента** — только инструменты чтения, лимиты шагов
  и вызовов, проверка из каталога, которая не выполнялась.

Метки написаны вручную по входным данным, а не скопированы из вывода
программы. Если код начнёт находить другое, случай не пройдёт.

## 8. Оценки ловят испорченные результаты

Хорошая проверка должна не только пропускать правильный ответ, но и отвергать
неправильный. Поэтому к каждому случаю применяются десять намеренных порч:

| Порча | Какая проверка должна сработать |
| --- | --- |
| Убрать ожидаемый факт | Полнота фактов |
| Сослаться на несуществующее наблюдение | Ссылочная достоверность |
| Убрать обязательное наблюдение | Полнота наблюдений |
| Добавить лишний факт | Нет неожиданных фактов |
| Убрать оговорку о неизвестной причине | Неизвестная причина |
| Пометить гипотезу агента подтверждённой | Неизвестная причина |
| Предложить выполненный перезапуск | Ограничения агента |
| Превысить лимит вызовов | Ограничения агента |
| Записать вызов инструмента изменения | Ограничения агента |
| Поменять статус качества данных | Качество данных |

Итог показывает, сколько порч применено и обнаружено. Если хоть одна прошла
незамеченной, команда завершается кодом `1`. Оценки выполняются в CI.

## 9. Контейнер

```bash
docker build -t ai-devops-agent:0.8.0 .
docker run --detach --name ai-devops-agent -p 127.0.0.1:8004:8004 -e APP_READ_TOKEN_SHA256="$READ_DIGEST" -e APP_WRITE_TOKEN_SHA256="$WRITE_DIGEST" -v ai-devops-agent-data:/data ai-devops-agent:0.8.0
SMOKE_READ_TOKEN="$READ_TOKEN" SMOKE_WRITE_TOKEN="$WRITE_TOKEN" uv run --locked python scripts/api_smoke.py --base-url http://127.0.0.1:8004
docker rm --force ai-devops-agent
```

Как устроен образ:

- две стадии: в первой uv `0.12.23` ставит только зависимости работы из
  `uv.lock`, во вторую переносится готовое окружение и папка `app/`;
- базовые образы закреплены по digest, поэтому тег нельзя незаметно подменить;
- в образе нет тестов, фикстур, лабораторий, документации, uv и кеша сборки;
- процесс работает от пользователя `app` с UID `10001`, без root;
- хранилище — `/data/investigations.sqlite3` на отдельном томе;
- `HEALTHCHECK` обращается к `/health` средствами стандартной библиотеки.

В образе есть только API. Там нет `git`, клиента Docker и доступа к Prometheus,
поэтому `--repository`, сборщик Docker и параметры телеметрии работают только
как CLI на машине разработчика. Подробно —
[поставка контейнера](instructions/container.md).

## 10. Проверка в CI и из чистого окружения

В [workflow](../.github/workflows/ci.yml) теперь две задачи. Задача `checks`
после прежних проверок запускает `python -m app.evaluate`. Задача `container`
выполняется после неё:

1. `docker build` с метками исходного репозитория и коммита;
2. проверка, что процесс запускается от UID `10001`, а pytest, Ruff и mypy
   в образ не попали;
3. запуск контейнера со случайными токенами, созданными для этого прогона;
4. `scripts/api_smoke.py`: отказ без токена, запрет записи токену чтения,
   сохранение, повтор без новой записи, неизменное чтение, проверка, агент, `404`.

«Чистое окружение» означает свежую копию репозитория без `.venv`, `var/`
и локальных файлов. Достаточно выполнить `uv sync --locked`, затем проверки,
оценки и smoke-проверку API — так и делает CI на новой виртуальной машине.

## 11. Ограничения поставки

- Образ не публикуется в реестр, не подписывается и не сканируется, ничего не
  разворачивается: для этого нужны реестр, учётные данные и владелец.
- Bearer-токены защищены настолько, насколько защищён канал: API должен
  оставаться на `127.0.0.1` или за TLS.
- Один токен чтения и один токен записи: нет пользователей, ротации и журнала
  аудита, любой читатель видит все отчёты.
- Шесть случаев оценок — небольшие вымышленные инциденты. Их прохождение не
  доказывает качество на настоящих инцидентах.
- Настоящая языковая модель по-прежнему не подключена.
